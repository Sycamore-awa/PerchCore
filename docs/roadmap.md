# 阅读器核心路线与任务

> 更新于 2026-11-14。本文是 PerchCore 后续开发的任务入口。已完成实现与验证见 [状态记录](status.md)，当前性能约束见 [性能与限制](performance.md)。未勾选项不再默认全部执行，以下文的当前优先级和启动条件为准。

## 项目目标

把 PerchCore 收口为一个真实电子书阅读器所需的稳定核心，重点提供 EPUB/TXT 处理、中文检索、稳定文本定位和可恢复的导入任务。保留当前 Rust/C/Dart 复用能力，但不再以“同时满足多个未知调用方的通用 SDK”作为近期目标。

完成标准：

- 真实阅读流程能稳定完成打开、目录、切片、检索、跳转、关闭和导入恢复。
- 接口、错误、内存所有权、字符单位和持久化格式保持现有版本契约。
- 后台解析或索引不因根注册锁卡住其他阅读操作；关闭和异常退出不泄漏句柄。
- 常见大文件不需要在 JSON 中生成整本十六进制副本，明确已知上限和失败行为。
- 每次扩展由阅读器实际问题驱动；没有真实场景的多平台包装、极端优化和可配置化不预先实现。

已确认的范围：Rust 核心、C ABI、纯 Dart 绑定、MIT、最小命令行示例；保留既有 crate 名称和 Locator 的 perch 扩展。EPUB/TXT 是主线，PDF 维持现有结构分析，不扩展正文抽取或渲染。同步合并和卷页几何保留但不作为当前主线。

## 2026-11-13 路线收缩

已有的样本集、性能基线、API/兼容契约、独立 context、EPUB/TXT 处理、检索与可恢复管线继续保留，不回退已建立的质量优势。

主线收缩为三项，现均已完成：

1. **IO-01（已完成）**：让常见文件路径不再经过整本 `bytes_hex`。
2. **LOC-01（已完成）**：让搜索命中可靠跳回源文本。
3. **STORE-01（已完成）**：让中断、损坏和缺失源文件有明确恢复行为。

完成这三项后先回到真实阅读器联调，由实际问题决定下一项，不再按原 M2–M5 清单自动往下做。

| 分类 | 任务 | 启动条件 |

| 按需精简实施 | TXT-01、IDX-01、LIMIT-01、ROBUST-01 | 真实文件、设备或用户操作已暴露问题 |

  已交付 [9 类样本与 manifest](../examples/data/corpus/README.md)、标准库生成器、只读重建校验和真实 Rust 回归；正确性样本随源码提供，性能/压力样本按倍数生成到 target。三平台 CI 已加入重建检查，当前本地实测与限制见 [状态记录](status.md)。

- [x] **BASE-02：测量完整处理链路。**

  已交付 [测量工具与边界](benchmarks/README.md)、Rust/C ABI/Dart 同步与 worker 的 [Linux 本地基线](benchmarks/2026-11-01-linux.md)。两套主报告各 194 个案例、每项 30 次重复，另有 8 项超限检查；记录全新 target 构建时间与真实进程 RSS。缓存未驱逐，冷缓存/设备数据未测，其他平台的原生 RSS 明确标为不可用；CI 只做工具冒烟，不设置耗时门槛。

  已交付 [完整方法参考](api-reference.md)、[可生成的目录、3 个 Schema 和请求/响应样例](../api/README.md)、持久 C/Dart AOT 客户端与 144 步实调一致性检查。生成漂移、方法/成功样例覆盖、规范请求拒绝及返回分支检查已加入 just/CI；Linux 本地验证见 [状态记录](status.md)。明确区分离线规范与现有运行时宽松解析，不改变 ABI、配额或持久化格式。

- [x] **API-02：制定版本与兼容策略。**
  覆盖 crate 版本、C ABI、JSON schema、Locator 扩展及 index.bin/text.json。先形成方案，区分新增字段、方法变更和持久化格式升级。验收：能说明旧调用方/旧产物如何检测兼容性、何时重建索引、如何返回不支持的版本；新增规则有旧版本夹具覆盖。
  已交付 [版本与兼容策略](compatibility.md)、`compatibility` 能力查询、C ABI v1 宏、JSON API v1.1 与带 major 的 Schema URN。Locator 未知版本稳定返回 `MODEL_UNSUPPORTED_VERSION`；`text.json` 读 v0/v1、写 v1，未知版本与损坏分开报错；index/text 升级规则为成组重建。固定旧夹具与 C/Dart 真实重放已覆盖新规则。

M1 收口后依据数据提出性能预算和回归门槛，确认后再写入验收标准；不直接继承旧 App 的打开时间或搜索指标。

## M2：上下文、并发与生命周期

- [x] **CTX-01：设计并实现独立上下文。**
  涉及 `perch-ffi` 注册表与各类句柄。提出显式 context/session 的创建、配置和销毁接口，明确句柄归属、资源配额和旧接口适配。验收：同进程两个上下文互不抢占固定配额；跨上下文误用可诊断；销毁一个上下文不破坏另一个；旧接口按确认的兼容方案继续工作。
  已按 [独立上下文设计](context.md) 实施：保留旧 `perch_call`，新增 `perch_context_call` 与 `context.open/close`；句柄全进程唯一、配额按 context 隔离、销毁成组释放。C/Dart 真实重放和类型化服务均已覆盖。

- [x] **CTX-02：缩短注册锁持有时间。**
  把文件 I/O、解析和建索引移出全局注册表锁，制定同一对象的 use/close 协调规则。验收：用可控制的长任务证明另一上下文或文档仍可读取；use/close 竞争没有死锁、误关或悬挂；比较并发读取延迟与 M1 基线。
  根注册表现在只分配和摘除 `Arc` 租约；book/TXT 只读共享，pipeline 按对象 Mutex 串行。close 后的新请求失败，close 前已取得租约的请求允许完成。可控阻塞回归已证明 pipeline 不阻塞另一 context 的 TXT 读取；Linux C ABI 双线程切片 p50 为 0.0347ms，M1 同机基线为 0.0377ms。

- [x] **CTX-03：完善取消、进度和异常退出。**
  涉及 `perch-pipeline`、`perch-jobs`、`perch-ffi` 和 Dart worker。明确取消粒度、可观察进度、在途请求和幂等销毁；线程模型和事件传递方式先形成方案。验收：取消不会把半成品标为成功；关闭能等待或取消在途任务；worker 异常退出后的句柄回收/恢复规则可验证，调用方不无限等待。
  [协作取消](cancellation.md) 把取消信号移出 pipeline 执行锁，Dart 类型化句柄通过独立控制 isolate 在普通 worker 忙时送达；step 在安全检查点返回 cancelled，取消后的 refining/indexing 状态可重做。`pipeline.progress` 从独立活动快照返回在途 book、阶段、粗粒度 checkpoint 和取消登记状态，Dart 同样可在 worker 忙时轮询。worker 异常退出后，context 及句柄由清理 isolate 回收；context 创建也由受跟踪的短生命周期 isolate 执行。原生 `context.close` 现在先拒绝新请求，再请求 pipeline 协作取消并等待所有已接受调用退出。粗粒度 checkpoint 已满足当前可观察进度验收；百分比留待真实 UI 需求定义工作量，不再阻塞 CTX-03 完成。

- [ ] **CTX-04：可配置资源配额。** `暂缓`
  用上下文配置表达文档数量、并行任务、结果上限等资源约束，提供清楚的超限错误。验收：资源能按上下文隔离，配置值与实际行为一致，非法配置被拒绝；默认值依据基线确认后落地。

## M3：大文件与内存

- [x] **IO-01：完善路径与缓冲区入口。**
  覆盖 `jobs.refine`、`book.open`、`txt.analyze` 等 bytes_hex 路径。优先增加可复用的文件路径入口，再评估借用缓冲区或流式输入；明确长度、所有权与生命周期。验收：正常大文件处理不需要生成整本书的十六进制字符串，返回有上限的结果；旧入口按兼容方案保留或迁移，Rust/C/Dart 同样本结果一致。
  已交付 [路径输入](io.md)：jobs.refine/book.open 支持互斥 path/bytes_hex，txt.inspect 按路径只返回统计，TXT 阅读继续 open/slice。Dart 同步/worker 门面已补齐；旧 v1.1/v1.2 Schema 与 161 组 v1.2 夹具冻结，IO-01 完成时 v1.3 的 34 方法/189 组 C/Dart 实调通过。仍全量读文件和解码，不引入流式/借用缓冲区或全文存储变化。

- [ ] **TXT-01：评估并实现大 TXT 存储策略。** `按需`
  比较分块解码、窗口缓存和文件映射等方案，处理 BOM、显式编码、跨块多字节字符、换行与随机跳转。验收：全文正确性与现有解码一致；Unicode scalar 定位稳定；大文件切片和重开不丢字、不重复；峰值内存满足已确认预算。编码索引和缓存失效规则写入文档。
  1/10/100 MiB Linux 实测已先消除不需要新存储格式的中间分配：合法 UTF-8 读取缓冲区直接转为 `String`，归一化/source-map 只保留前 `max_chars`。100 MiB 整进程 max RSS 从 558.5 MiB 降至 p50 409.1 MiB。`txt.open` 仍全量驻留正文，TXT-01 保持未完成，等待移动真机预算再决定是否引入分块/映射复杂度。

- [ ] **IDX-01：控制索引构建与加载成本。** `按需`
  测量正文与倒排的重复驻留，评估分批抽取、增量构建、正文存储和按需加载。验收：CJK、单字、拉丁短语及跨分片命中不退化；正文与索引一致性校验保留；新旧样本的耗时和峰值内存可比较。
  真实 1/10/100 MiB TXT 已触发并完成一个限量查询切片：`book.search limit=20` 改为在索引内部达限即停，1 MiB 高频词从 4620.567ms 降至最终 5 轮 p50 3.583ms，10/100 MiB 为 7.704/7.540ms。索引构建/加载的长期驻留策略尚未改动，所以 IDX-01 保持未完成。

- [ ] **LIMIT-01：统一输入与输出预算。** `按需精简实施`
  定义文件/章节/解压数据、抽取字符、查询结果和缓存等限制，向调用方区分“完整”“截断”“超限”“取消”。验收：无法在预算内处理的样本得到稳定错误或明确截断结果，不静默报告全书索引完成；部分产物能够清理或重试。

## M4：定位、持久化与可靠性

- [x] **LOC-01：建立索引文本到源文本的映射。**
  涉及 `perch-jobs::BookText`、章节区间和命中定位。保留归一化前后的对应关系，明确 EPUB href 与 TXT 原解码字符偏移。验收：空白归一化、emoji、中英混排和跨章节样本均能从命中回到正确源文本；旧产物按版本规则读取、降级或重建。
  已交付 [源位置契约](source-location.md)：MappedBookText 保持旧 BookText 字段与抽取签名，TXT 保留原解码 scalar/UTF-8 端点，EPUB 保留 href、局部节点路径与 scalar/UTF-16 端点，人工分隔符向内吸附。可选 sourceMap v1 随 PathStore 导入落盘，旧产物仍可搜索、定位用专用错误提示重建。JSON API v1.4 的 35 方法/256 组 C/Dart 重放覆盖源切片、节点解析、截断与所有权；v1.3 Schema/189 组夹具冻结。尺寸、打开/重开与进程 RSS 见 [LOC-01 测量](benchmarks/2026-11-13-linux-source-map.md)。不自动重建、模糊重锚或实施阅读器页面跳转。

- [ ] **LOC-02：收口上下文重锚契约。** `暂缓`
  整理现有 CFI/上下文算法，提供匹配质量、歧义和失败信息，避免把低置信结果当成精确定位。验收：重复文本、缺失锚点和内容变更都有确定的结果；第二种调用方能够验证命中原文。实际渲染跳转仍由阅读器集成验收。

- [x] **STORE-01：明确产物恢复与迁移。**
  涉及 PathStore、索引持久化与任务状态。覆盖写入中断、状态/索引损坏、缺失源文件、版本升级和重试；说明产物目录的单拥有者规则。验收：损坏单书不阻断其他书；恢复不把半成品当成功；旧版本夹具可读取或明确触发重建；多进程支持另行决策。
  PathStore 现在在打开时审计检查点、refinement 和 index/text/sourceMap 产物组。单书状态损坏降级到 registered，refinement 无效从阶段二重做，Ready 的索引组缺失、损坏、版本不支持、正文不一致或缺 sourceMap 时降级到 indexing。审计不删除旧产物；重新提供源路径后幂等成组重建，源缺失进入既有失败/退避流程。C/Dart 真实重放覆盖损坏 Ready 索引的降级与重建；多进程仍不支持，产物目录必须单拥有者。详见 [存储契约](storage.md#store-01-恢复规则)。

- [ ] **ROBUST-01：损坏输入与性质测试。** `按需`
  对 ZIP/XML、TXT 编码、PDF 结构、Locator 和索引文件建立可复现的坏样本、性质测试及 fuzz 入口。验收：字符转换往返、跨分片查询和损坏产物处理符合契约；发现的问题保留最小回归样本；超时或资源限制可观察，不将全部失败归为一个通用错误。
  已完成与 STORE-01 直接相关的确定性小切片：12 种 refinement/index/text/sourceMap 缺失、损坏与未来版本组合均验证单书隔离、正确降级和重新登记源文件后的完整重建。其余广泛输入损坏与 fuzz 工作仍按真实问题启动，本项不勾选完成。

## 维护方式
