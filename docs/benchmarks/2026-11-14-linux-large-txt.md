# 2026-11-14 Linux 真实阅读器大 TXT 冒烟

本次使用同级 PerchReader 的 `tool/bench_large_txt.dart`，通过公开 Dart `PerchWorker` / `PerchServices` 调用 release `libperch_ffi.so`。每轮新建源文与产物目录，执行指纹、pipeline 导入、关闭、worker 重启、Ready 恢复、书籍加载、“文字” `limit=20` 搜索、TXT 打开和首页 900 字切片。

## 问题与修复

修复前，1 MiB 单轮的搜索耗时为 4620.567ms；10 MiB 运行超过 60s 仍未返回。FFI 当时调用不限量 `Index::search`，然后才对已构造的全部命中执行 `take(20)`；每条命中的摘要还会重复遍历全文统计字符数。

第一个修复新增 `Index::search_limited`，按字符偏移顺序生成命中，达到 limit 后立即停止扫描；FFI 将 limit 直接传入索引。`Index::char_count` 改为从已有分片尾界 O(1) 取值。

100 MiB 扩展测量又暴露了一个可避免的峰值：合法 UTF-8 先读入 `Vec<u8>`，然后复制整本为 `String`；导入在最终只保留 5M 字符时，仍先构造全部归一化正文和 source-map。第二个修复让所有权路径直接把合法 UTF-8 读取缓冲区转为 `String`，并从归一化开始就只保留前 `max_chars` 的文本与映射，同时继续无额外全文输出分配地扫描剩余内容，以保持 `decodedChars` / `decodedBytes` 元数据。索引文件格式、响应形状和命中顺序均不变。

## 结果

修复后每个尺寸独立运行 5 轮；下表为中位数。原始毫秒数组见 [JSON](2026-11-14-linux-large-txt.json)。

| 指标 | 1 MiB | 10 MiB | 100 MiB |
|---|---:|---:|---:|
| 源文字节 | 1,048,576 | 10,485,760 | 104,857,600 |
| 源文字符 | 611,696 | 6,116,720 | 61,166,960 |
| 索引字符 | 611,696 | 5,000,000 | 5,000,000 |
| 是否截断 | 否 | 是 | 是 |
| 分片 / token | 150 / 38 | 1,221 / 38 | 1,221 / 38 |
| 产物字节 | 2,114,602 | 17,278,263 | 17,278,265 |
| pipeline 精修步骤 p50 | 2.546ms | 15.920ms | 79.153ms |
| pipeline 索引步骤 p50 | 13.984ms | 112.212ms | 177.830ms |
| 恢复打开 p50 | 1.877ms | 13.048ms | 12.850ms |
| 书籍加载 p50 | 1.602ms | 12.069ms | 12.411ms |
| 高频词搜索 p50 | 3.583ms | 7.704ms | 7.540ms |
| TXT 打开 p50 | 1.310ms | 10.976ms | 103.277ms |
| 首页切片 p50 | 0.425ms | 0.660ms | 0.689ms |
| 整个 Dart 进程 max RSS p50 | 278,822,912 | 292,679,680 | 428,941,312 |

1 MiB 搜索相对修复前单轮缩短约 1,290 倍。10/100 MiB 不再随重复命中数量全量展开，搜索保持在 8ms 以内。100 MiB 内存修复前单轮 max RSS 为 585,596,928 字节，修复后 5 轮 p50 为 428,941,312 字节，降低 156,655,616 字节（约 149.4 MiB / 26.7%）；精修从 111.107ms 降至 p50 79.153ms，索引从 212.380ms 降至 177.830ms。

100 MiB 的 `txt.open` 仍需要完整解码正文并建字符/行索引，因而耗时与常驻内存仍随文件增长。进一步降低这部分需要分块解码、映射或窗口缓存等 TXT-01 存储取舍；本次不宣称 TXT-01 或完整 IDX-01 已解决。

## 限制

这是同一 Linux 宿主、未驱逐页缓存的小样本冒烟，每轮包含 Dart VM/worker 启动但不分离记录核心独占 RSS。`ProcessInfo.maxRss` 是整个 Dart 进程的生命期高水位，不能直接归因给单个操作。10/100 MiB 案例受默认 5,000,000 索引字符上限影响，不是全文索引吞吐。移动真机、取消和可观察进度仍需后续数据。
