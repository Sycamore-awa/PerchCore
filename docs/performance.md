# 性能设计、证据与限制

## 已有设计

- TXT 每 256 个 Unicode scalar 建一个字符/字节抽样点，避免每次定位从头扫描。
- 搜索使用按分片的倒排列表，查询时预筛候选片，再做精确短语扫描；不需要中文词典。
- 索引按书落盘并按需加载，避免整书库索引同时常驻内存。
- 文本读取使用句柄与有上限的切片，减少跨语言全文传输。
- 导入分阶段执行，支持优先级、配额、退避和恢复。

## 已有性能证据

原项目登记基准曾测得 1000 本约 56ms。它只覆盖首尾采样读取、指纹和登记规划，不包含原文件复制、书库事务、完整解析、索引、冷缓存或设备界面。

在本仓库重跑：

```sh
cargo run -p perch-import --release --example bench_register
```

此数字不能推出“任意书籍瞬开”或完整导入吞吐。抽样索引空间估算也不等于进程峰值内存。

## 当前限制

| 环节 | 当前行为 | 后续方向 |
|---|---|---|
| TXT 打开 | 全量读文件和解码，正文驻留内存 | 分块/映射输入、解码窗口和明确文件预算 |
| 全文索引 | 正文和倒排在建索引阶段驻留；默认最多抽 500 万字符 | 内存预算、增量建索引与截断策略配置 |
| FFI 文件传输 | 部分接口仍使用 bytes_hex，字符串为原字节两倍长度 | 路径/缓冲区/流式 API |
| 并发 | 进程全局 Registry/Mutex；管线步骤可能阻塞读取 | 独立上下文与细粒度对象锁 |
| 生命周期 | worker 异常退出不自动释放 Rust 遗留句柄 | 显式 session 销毁和恢复规则 |
| 搜索定位 | 索引正文经过归一化，EPUB 为粗 Locator | 精确文本重锚、渲染器集成验证 |

## 待建立的基线

分别测 EPUB/TXT/PDF 结构打开、正文抽取、建索引、查询、落盘/重开和并发读取；报告样本大小、编码、冷/热缓存、CPU、内存、工具链，以及 p50/p90/p99 和峰值内存。

移动端延迟、功耗和吞吐需要实际设备。损坏 ZIP、极大章节、超长单行和索引损坏需要额外压力与模糊测试；本次提取不声称已完成这些验证。
