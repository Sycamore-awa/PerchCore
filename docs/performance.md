# 性能设计、证据与限制

## 已有设计

- TXT 每 256 个 Unicode scalar 建一个字符/字节抽样点，避免每次定位从头扫描。
- 源映射使用连续区间，定位在内存中每 256 scalar 抽样 UTF-8/UTF-16 边界；产物不逐字符保存坐标。
- 搜索使用按分片的倒排列表，查询时预筛候选片，再做精确短语扫描；不需要中文词典。
- 索引按书落盘并按需加载，避免整书库索引同时常驻内存。
- 文本读取使用句柄与有上限的切片，减少跨语言全文传输。
- 导入分阶段执行，支持优先级、配额、退避和恢复。

## 已有性能证据

原项目登记基准曾测得 1000 本约 56ms。它只覆盖首尾采样读取、指纹和登记规划，不包含原文件复制、书库事务、完整解析、索引、冷缓存或设备界面。

在本仓库重跑：

```sh
cargo run -p perch-import --release --example bench_register
```

此数字不能推出“任意书籍瞬开”或完整导入吞吐。抽样索引空间估算也不等于进程峰值内存。

## 当前限制

| 环节 | 当前行为 | 后续方向 |
|---|---|---|
| TXT 打开 | 全量读文件和解码，正文驻留内存 | 分块/映射输入、解码窗口和明确文件预算 |
| 全文索引 | 正文和倒排在建索引阶段驻留；默认最多抽 500 万字符 | 内存预算、增量建索引与截断策略配置 |
| FFI 文件传输 | 精修/索引/PDF 可用 path；TXT 统计用 inspect、阅读用 open/slice，保留旧 bytes_hex | 缓冲区/流式 API 按需评估 |
| 并发 | 根 Registry/Mutex 只做句柄管理；book/TXT 只读共享，pipeline 按对象串行；close 后拒绝新请求，已取得租约的请求完成 | 已完成 CTX-02；取消、等待在途任务和异常退出留给按需的 CTX-03 |
| 生命周期 | 显式 context 可成组销毁；worker 异常退出仍不会自动调用 close | CTX-03 异常退出回收与恢复规则 |
| 搜索定位 | TXT/EPUB 连续源映射与两个端点；旧产物仍搜索，缺少映射时定位提示重建 | 已完成 LOC-01；源文件变更后的重锚、页面跳转和高亮由阅读器联调 |
| 产物恢复 | `pipeline.open` 顺序读取每本 Ready 书的 refinement/index/text 并验证映射与正文一致性；不同时常驻所有书 | STORE-01 已收口正确性；大书库冷启耗时尚未建立基线，如成为真实瓶颈再评估代际 manifest 或延迟审计 |

## 可复现本地基线

[BASE-01 可复现样本集](../examples/data/corpus/README.md) 与 [BASE-02 测量工具](benchmarks/README.md) 已完成。[2026-11-01 Linux 基线](benchmarks/2026-11-01-linux.md) 提供两套各 194 个案例的原始 JSON、全量表格、吞吐、RSS 和构建记录，覆盖登记、打开/解码、精修、抽取、建索引、查询、存储/重开、切片、管线与 C ABI/Dart 调用。资源预算仍需确认，并作为后续 CTX/TXT/IDX 任务的验收依据。

约 144 万字符的长行样本中，Rust 建索引 p50 为 30.633ms，Registered → Ready 管线为 36.734ms；Dart 全文 analyzeText 为 84.367ms，末尾 800 字 txt.slice 为 0.0070ms。UTF-8 样本的 1,024 命中查询 p50 为 36.116ms，表明摘要构造和先计算全部命中再限量的路径需要后续测量与优化。

上述为预热/准备已访问、系统页缓存未控制的 Linux 宿主结果。RSS 包含各语言运行时、准备和校验；写入未做 fsync。64 倍主基线与 256 倍长行截断检查已记录，设备、冷缓存、deflate EPUB、复杂 PDF 和功耗仍未测量。损坏 ZIP、极大章节和索引损坏需要 ROBUST-01 的额外压力与模糊测试；本地结果不构成移动端性能承诺。

## LOC-01 源映射测量

[2026-11-13 LOC-01 报告](benchmarks/2026-11-13-linux-source-map.md) 与原始 JSON 记录正确性集和 scale=64 性能集的 56 项测量，每项 30 次计时、2 次预热。比较产物大小，以及同一当前实现加载完全相同 index/body 时可选 sourceMap 的有无；路径打开只测新实现，不提供改动前抽取的基线。

| scale=64 样本 | 原 text 字节 | 带映射 text 字节 | 增量字节 | 无映射加载 p50 ms | 带映射加载 p50 ms |
|---|---:|---:|---:|---:|---:|
| UTF-8 | 92,273 | 144,637 | 52,364 | 0.1035 | 1.7046 |
| long-line | 3,014,779 | 3,014,937 | 158 | 2.4777 | 3.5733 |
| EPUB3 | 129,277 | 129,678 | 401 | 0.1185 | 0.1833 |

连续长行只需一个源区间；有大量 CRLF/空行折叠的 UTF-8 样本需要 4,097 个区间，产物增量和加载校验成本更高。长行路径打开 p50 为 33.5827ms，已打开句柄上的定位为 0.0059ms。带映射加载的最大记录进程 RSS 分别为 UTF-8 29.727MiB、长行 34.781MiB、EPUB3 26.504MiB；完整分布和原始计数见报告。

RSS 每项使用全新进程，保留每轮 VmRSS 和最终 VmHWM，报告取两者的最大记录值。Linux 计数存在近似与异步更新，最终 VmHWM 可能略低于先前 VmRSS，不能保证捕获所有瞬时峰值。进程包含 Python/Rust、准备、操作与校验，进程间差值不能解释为映射的独占分配量。页缓存未控制，复现命令与字段见 [测量说明](benchmarks/README.md)。
